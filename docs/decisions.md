# Decisions

- Follow voice-checkin: Node 24, ES modules, strict erasable TypeScript, src/tests separation and Node's built-in runner. No runtime dependencies. TypeScript documents the adapter boundary; runtime validation still does the security work.
- Keep only core as an npm workspace for now. Specification folders do not need executable package scaffolding.
- Inject the reader into the parser. This makes missing and rejected inputs testable without giving the parser filesystem-write or network capabilities. This is architectural separation, not an OS sandbox against malicious plugin code.
- Whole-file JSON remains the implemented Instagram reader. The contract explicitly permits streaming; implementation is deferred, not architecturally excluded. See the memory decision below.
- Keep snapshot provenance outside the ten-field Activity schema and platform extras in side tables. Future comparison can preserve both exports without changing every platform row.
- Use versioned JSON/JSONL initially for inspection and lossless records. Introduce a database only for a demonstrated query or scale need.
- Use case-sensitive Instagram shortcodes as URL fallback identity, preserving raw_id as preferred event identity and keeping the observed path type separately.
- Generate two aggregate summaries by default. Removing all creator identity would defeat the user's intended assistant-assisted analysis. Disclosure labels inform the user's choice; HINDSIGHT never uploads the files.
- Source export relocation was explicitly requested before repository creation. Future ingestion never moves or modifies sources. The later quarantine proposal was cancelled; no privacy-driven deletion of disposable copies is planned either.
- Step 2's full acceptance table requires collection interpretation. Move that parsing work forward while keeping persistence integration in step 3.
- Repeated Caption labels exist in the reference data. Select the first in source order for the unified title, retain every value in post extras, and emit an informational diagnostic. Do not treat repetition as a malformed event or concatenate alternative captions.
- Observation IDs are deterministic source-file/row references local to one parse. The later snapshot layer must scope them to its snapshot ID; event keys omit source positions so reordering does not change matching identity.
- Parse status partial includes unmatched placements even when acceptance passes. Acceptance means matching the measured export; complete would incorrectly conceal known gaps.

## Memory ceiling and future YouTube ingestion

The user's Instagram run measured 187.7 MiB RSS for roughly 30 MB input (about 6x as a rough ratio). Our recorded step 2 run measured 212.0 MiB; step 3 measured 217.7 MiB. RSS includes the runtime, buffers, parsed objects and normalised rows. These ratios vary and are not linear predictions.

The user supplied a 100–300 MB YouTube watch-history planning scenario; we have not benchmarked such an export. Today's 32 MiB whole-file ceiling would reject it. A naive 6x extrapolation at 300 MB suggests approximately 1.8 GB RSS, an unacceptable design assumption for unattended family laptops, not a measured result. Raising the whole-file limit is not the plan.

ParserInput now optionally exposes iterateJsonRecords alongside readJson, with separate total-byte/per-record limits, backpressure, cancellation and terminal validation. PlatformParser also permits incremental-only adapters: streaming input would not suffice if normalised output still had to accumulate in ParseResult.events. Types and synthetic contract demonstrations exist; no streaming JSON reader, incremental coordinator or YouTube implementation exists. See streaming-contract.md for provisional-record and malformed-tail rules.

The step 3 side-table bundle is still buffered and capped at 32 MiB. Future storage and aggregation must consume incremental emissions and bound their own indexes and sorting. An iterator interface alone is not a bounded-memory guarantee.

## Persist side tables before full snapshots

One versioned bundle contains exactly the three Instagram side tables, marked personal and untrusted, scoped to a caller-supplied snapshot ID. Validate references before publication and after loading. Unmatched in this snapshot means null savedObservationId and savedAt; ambiguous joins retain candidates and select none. Empty collections and ordered caption variants survive persistence.

Publish by linking a fully written, synced temporary file to a new destination name, then removing the temporary name. This cannot overwrite an existing target: identical retries succeed, changed contents under one ID fail. It requires same-filesystem hard-link support (verified on local Windows); unsupported filesystems fail clearly. File sync does not guarantee directory-metadata durability across power loss. An interrupted process may leave an unpublished temporary file. Full snapshot recovery belongs to step 4.

This standalone artifact is not a complete snapshot: event persistence and source manifests remain step 4. The existing caption-selection decision is supported and bounded by the findings in caption-investigation.md; first_in_export does not mean latest.

## Step 4: outputs and complete snapshots

Complete snapshot publication is now implemented separately from the earlier side-table-only API. Each --output root contains independent snapshot directories, each with the four primary outputs, two human-readable logs and internal observations, side tables, diagnostics and manifest. A generated UUID avoids inferred export dates and name collisions; an explicit ID must be unused. Reports describe one snapshot and never sum overlapping exports.

CSV serialization prefixes dangerous text cells with an apostrophe before quoting. JSONL retains the parsed original text. Tests inspect the written CSV with an independent decoder and name spreadsheet formula injection explicitly. This is export-time handling, not a change to creator identity or authoritative source content.

The anonymous summary is assembled from an allowlist of count/date/distribution fields. Detailed output adds creator identity and weekly creator frequencies. Tests check exact forbidden fields and replace source identities/content with canaries: anonymous output remains unchanged. Group by platform and creator_id, never display name; missing creator IDs are counted separately without inventing a creator. The creator CSV keeps the agreed five columns; identically named creators can appear as separate rows. Detailed JSON supplies IDs for disambiguation. Display name is the latest observed nonempty name, with deterministic source-order tie handling.

Partial imports succeed when usable activity remains, with explicit omission messages. An empty valid export succeeds with empty files. Missing folders, unusable data and write failures return nonzero. Read errors distinguish empty files and the 32 MiB limit rather than exposing raw filesystem/JSON exceptions. parse-report.txt leads with plain English; machine detail stays in diagnostics.json. Missing captions are retained and described accordingly.

Snapshot files are staged under the resolved output root; only a completely written directory is renamed into place. A per-ID lock serialises cooperating writers, existing targets are rejected, and ordinary failure cleanup touches only operation-owned paths. A terminated process may leave a hidden stage/lock; readers must use completed snapshot directories. Neither this nor file sync guarantees directory-metadata power-loss durability. Integrity hashes detect accidental changes, not malicious re-signing of a manifest. Output is forbidden inside the selected source tree and the project repository.

All current artifacts remain capped at 32 MiB; no streaming implementation was added. The original next-step changepoint proposal was explored in a design and then superseded, after descriptive exploration, by the lifecycle/burst design below. Its historical preregistration remains available; it was not run on the real data.

## Post-exploration product and architecture decisions — current authority

These decisions supersede conflicting future plans above. This revision changes documents only; browser, lifecycle/burst, session fitting, annotation and MCP code remain unimplemented.

1. **A memory aid for trusted friends/family.** The user's description is corroborating evidence for their life story: memories of university, holidays or a period of health content belong to the user. The tool supplies evidence, such as a creator's dated observations; the user supplies meaning. Never narrating or interpreting their life is the mechanism. No launch, virality, adoption funnel, app-store strategy, export-turnaround optimisation or strangers' beta plan.
2. **Collections are a recent system, not historical labels.** 67/73 folders were created in 2026, 30 in January; 4,047/4,809 saves date to 2026; 90.96% of 2025 saves are unfiled. Current-folder topic evidence is dense roughly December 2025–August 2026 and sparse earlier. Earlier liked activity has creator/hashtag evidence, not historical collection labels. No seamless whole-history topic timeline. Collection dates are object creation dates, never filing dates.
3. **Preserve the hypothesis result and the confound.** Once/twice-account event share goes from 17.50% in 2021 to 67.93% in 2026: the user's stated frequency hypothesis was not supported and the observed direction is reversed. No explanation is assigned. In the school comparison, daytime weekday share rises 17.77% to 25.18% while events fall 1,418 to 544; the 2022 low-count interval is inside the after-window. School departure and the supplied TikTok-migration context overlap. Neither can be credited with causing the observations.
4. **Annotations are core, optional and user-owned.** Locally authored dated points/periods, optional uncertainty, plain-text notes, separate revisions and explicit portable save/import. They are never required or uploaded. A rendered timeline replaces the blank ground-truth form. It does not make post-viewing annotations independent ground truth; future confirmatory use needs a frozen revision and disclosure of prior exposure. Shape: [browser-and-annotations.md](browser-and-annotations.md).
5. **Cancel the packaged executable; choose offline HTML.** One downloadable application file bundles runtime code and assets. No installer, server or account; Windows/macOS browser compatibility is an acceptance target, not yet tested. The audience's trust burden justifies the decision independently of marketing metrics. Microsoft confirms that signing alone does not eliminate reputation warnings; the user-supplied 95% drop-off and annual certificate-price figures are not verified project evidence and are not adopted as quantitative design premises. [Microsoft SmartScreen documentation](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation).
6. **Core remains the engine; browser, CLI and MCP are shells.** readJson is a usable injected boundary, but Buffer-based repair, filesystem ingestion/persistence and Node imports still require separation. Report rendering takes an in-memory model, not an output path. Saving a personal bundle/HTML is explicit; a page cannot assume it can overwrite itself. file-origin storage and worker/CSP compatibility require tests. CLI is not an .exe substitute; MCP is built last.
7. **Do not promise browser memory from Node input bytes.** Instagram's roughly 30 MB is a reasonable first target, not measured browser headroom. Decompression, parsing and copies matter. Workers are useful for Instagram responsiveness too, but do not bound memory. YouTube requires streaming JSON-array consumption, coordination, bounded state and persistence; File.stream plus a worker is not sufficient, and input JSON is not automatically NDJSON. Prior memory measurements and the synthetic JSD benchmark are not browser/burst benchmarks.
8. **ZIP is selective browser intake, not full extraction.** A browser decompression API is not a full archive selector. One audited, pinned, self-bundled ZIP dependency is justified for evaluation (zip.js candidate); no dependency is installed now and no unmeasured bundle-byte claim is made. Costs include codec bytes, metadata validation, selected-entry inflation, memory limits and adversarial/browser tests. Stream/inspect metadata, open only permitted payloads, and state that metadata was read. Full untrimmed-export testing moves into step 8 rather than disappearing with quarantine.
9. **Cancel quarantine permanently in favour of read-only allowlisting.** This resolves the original delete-versus-read-only contradiction. Do not enumerate sensitive content to delete it. Unknown file additions remain outside reader authority. Generate disclosure from the descriptor plus actual read audit, with reviewed path-category metadata where needed. Today four paths are declared but liked_comments is intentionally not read. Allowed contents can still hold private information. Update future quarantine.log policy wording to no removals / declared_paths_only while preserving old artifact semantics and status bytes. User guidance may suggest deleting the ZIP themselves; deletion is not a subsystem. [Threat model](threat-model.md).
10. **MCP is retained as the central adversarial demonstration.** Indirect prompt injection in export captions/labels becomes a concrete attack path when a selected-data tool response reaches a model. Least authority, explicit selection, provenance, bounded excerpts, no filesystem/network/write tools and synthetic attack tests are the design. A local server cannot guarantee an external client will not transmit its results; that permission boundary must be explicit. Browser/core remain AI-free and offline. No promise of prompt-injection immunity or automatic Ollama integration.
11. **Kleinberg bursts replace changepoints; lifecycles are the backbone.** Independent lanes permit overlapping recorded concentrations. Singletons are excluded explicitly; they are not mathematically guaranteed to self-exclude, and relative-rate handling needs a declared denominator. Sustained-contact ordering is a separate policy, not a property burst detection supplies automatically. The old ERAS design is superseded, not represented as a failed experiment. Define new configurations, validation and limitations before running anything. [Step-6 design](lifecycles-and-bursts.md).
12. **Invert YouTube definitions transparently; disclose our own windows.** First recorded/new after >12 calendar months, observed active months in a rolling year, and unique creators over 28 days are the basis. The official wording conflicts at exactly six months, so keep six explicit instead of inventing a boundary. Activation 7–30 days, follow-up windows near day 7/30/90 and elapsed-time markers 30/60/90 are configurable conventions, not validated norms or judgements. Display last recorded here, never churned/lost/abandoned. Repeat-creator lifecycles and aggregated singleton counts preserve coverage without thousands of unsupported curves.
13. **Derive a session split if supported; otherwise use 60 minutes.** Plot log gaps, fit the declared two-component mixture, inspect a genuine valley and use its crossing only when fit checks hold. Report fallback honestly. No fit is run now. The cited research supports a heuristic with exceptions, not an Instagram validation or a universal law. Preserve the existing 15/30/60 research tables as historical; the new UI is not built from their percentile columns.
14. **Swimlane Gantt is the target, not a claimed universal research winner.** One lane per current topic or creator, one bar per bounded recorded burst, overlaps and coverage visible. Plain SVG needs no chart library. Rectangles are simple; accessibility, annotations and uncertainty are not honestly costed as a whole product in 50 lines. Order by active months/weeks/sessions, not raw count. Shape: [browser-and-annotations.md](browser-and-annotations.md).
15. **History, context and user-supplied factors; no normative scoring.** No percentiles in user output, no other-person comparisons, leaderboards, targets, discrepancies, moralised vocabulary or failure framing. No automated better/worse self-comparison scorecards either. Historical exploratory contrasts explicitly requested by the user remain research records, not product recommendations. Internal rate comparisons and engineering pass/fail checks are still needed to compute/validate a model; neither is a judgement of a person. Rendering cannot guarantee reflection rather than rumination. The cited Loerakker PDF is dated December 2023; unverified claims about 2024 causal effects, Wrapped complaint rankings or Gantt superiority are not treated as settled evidence.
16. **Action time and intention limits are permanent.** Saved time is not publication or viewing time; old content saved later cannot be distinguished from recently published content. A save can mean reference, aspiration, shopping, recipe or meme. Current folders partly clarify the recent window only. No life narrative, causal diagnosis or complete-interest claim follows.

Current delivery order: 6 lifecycle/burst design then implementation by review; 7 snapshot diffing; 8 self-contained browser report with annotation and allowlist ZIP disclosure; 9 streaming then YouTube; 10 CLI then MCP as the last centrepiece. The cancelled quarantine and .exe milestones do not reappear under other names.

## Step 6 implementation after separate approval

Creator lifecycles shipped independently before session fitting and folder bursts. No browser or annotation work was included. The two-date/two-observation bar support policy and complete nine-setting/two-denominator grid are unchanged. State zero is the initial prior state, and elevated first bins pay the upward cost; exact cost ties prefer lower total intensity then earlier upward boundaries. A date-only export leaves its endpoint week conservatively unassessed. Calendar lifecycles use an explicit inclusive UTC export-day endpoint and Brisbane local dates by default.

Session plots distinguish weighted-component crossings from mixture valleys. All three numerical fits and plots were reviewed: crossings are 14.34 minutes saved, 43.24 liked, 32.14 combined. Unsupported inputs retain the 60-minute fallback. Plot-review acknowledgement is explicit in command provenance; the fit alone does not silently authorise a derived cutoff. No long gap was removed.

The fixed primary produced 46 outer intervals across 34 folders, with 29 additional nested intervals. Only three outer intervals preserve identical endpoints across all nine settings. This sensitivity is evidence against presenting these dates as established phases; there is no parameter promotion or concealment of unstable results. Named comparisons and all grid output remain outside Git. The descriptive multi-year layer does not depend on burst stability.

The complete final Node command measured 4.778 seconds and 464.63 MiB peak RSS; detector-only primary process peak was 177.38 MiB. Output materialisation has a substantial memory cost even on this snapshot. These are not browser or streaming guarantees. No dependency was added; the browser milestone must benchmark its own representation and memory. Full evidence and reproduction commands: [step-6-validation.md](step-6-validation.md).

## Step 6 accepted; step 8 presentation design before diffing

The memory-aid use is locating a period that prompts recognition, not dating a lived phase. Eighteen of 46 primary outer intervals retain overlap in every grid setting, including three with exact weekly endpoints. Preserve the three exclusive visual tiers (3 exact, 15 additional overlap, 28 primary-only), measured fuzzy geometry and visible annotation recording context. A retrospective memory can supply meaning and uncertain dates without becoming independent detector validation.

No-primary-bar folders have their own positive descriptive section. Do not classify all 39 as steady: 17 have bars elsewhere in the grid, two have no assessed weeks and 15 have records across at least two assessed weeks. Show recurrence, sparsity and coverage directly, not failure labels or invented steady interests.

The report opens with observed coverage and saved/liked divergence, then the multi-year creator backbone, then the separate recent-folder window. Plain SVG remains sufficient; no chart dependency or browser implementation is added in this revision. [Step-8 presentation design](step-8-report-design.md) is the review artifact.
