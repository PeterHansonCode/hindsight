# MCP shell — final portfolio/security milestone, specification only

MCP is retained, built last in step 10 over the same portable core as browser and CLI. It is the primary intended realisation of indirect prompt injection via third-party export content, not an optional hypothetical feature. It is not yet an implemented/live server. The browser/core memory aid remains AI-free; this opt-in shell supplies selected evidence to a model client and never authors the user's life meaning.

Expose explicitly selected snapshots through local transport such as stdio. Aggregate access is default; bounded untrusted excerpts require separate explicit permission. User annotations are excluded unless deliberately included. No arbitrary paths, filesystem enumeration, contact access, write/delete tools, shell execution, URL fetching or outbound network capabilities. Source text, labels and imported notes cannot change permissions. Responses carry source/snapshot references, schema/config versions, coverage and contentTrust; logs omit personal content.

Use the same declared-path reader boundary and generated read disclosure as other shells, including metadata-versus-payload distinctions. No quarantine or content-sanitisation promise. Current folders label the recent December 2025–August 2026 save window only, not historical likes; saving timestamps are not publication or viewing times. MCP must preserve these caveats and user-authored annotations separately rather than turn them into authoritative narratives.

A local server is not an offline guarantee for the client: a cloud model may transmit its tool results. Explain that before exposing personal data and never connect automatically. No automatic Ollama integration is planned. A caption asking to ignore instructions and disclose contacts must remain data; contacts are outside ingestion and server capabilities. Restrict authority rather than rely on the model obeying a delimiter or regex cleaner. The server cannot constrain other tools the host grants its model.

Build synthetic adversarial demonstrations for forged instructions, attempted file/contact access, outbound disclosure, annotation injection, capability escalation and log/error leakage. No raw personal export may be sent to a model during development without explicit authorisation. Document residual client risk and avoid any immunity claim. This constrained, tested attack surface is the portfolio story. See ../../docs/threat-model.md and ../../docs/browser-and-annotations.md.
