# Security specifications — quarantine cancelled

There is no quarantine engine or deletion taxonomy to implement. This specification folder remains a pointer to cross-shell boundaries and adversarial tests, not a pending subsystem. The original quarantine/delete requirement is superseded permanently by read-only originals and declared-path payload access.

Unknown files remain unopened. Generate disclosure from the adapter's authority and actual read audit; distinguish archive metadata from payload reads and private content inside allowed fields from excluded file categories. Future quarantine.log wording records no removals / declared_paths_only, while old snapshot statuses and bytes retain their historical meaning. A user may choose to delete their ZIP; the tool does not.

ZIP safety, expansion bounds, disclosure and untrimmed-export tests belong to step 8. Model-facing injection defenses belong to the final MCP shell at step 10, where third-party text reaches an LLM client. Existing filesystem/CSV/disclosure tests remain applicable. No PII cleaning, archive extraction or new security code is implemented by this revision. See ../../docs/threat-model.md and ../../docs/BUILD-CONTRACT.md.
